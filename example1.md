# Example1 Three.js 3D demo
Implemented in `example1.html` (single scene, Three.js via unpkg CDN import map).

## Scene
- One scene, dark background (0x050508), ACES tone mapping.
- 1000 rounded-corner cubes (`RoundedBoxGeometry`, 4 segments, 0.16 radius).
- Cube centers evenly distributed over a sphere of radius 9 using Fibonacci sphere sampling. The sphere itself is not drawn as a primitive.
- Camera (PerspectiveCamera, fov 60) looks at the sphere center. Set by hand to (0, 0, 10) — outside the cube shell (radius 9), viewing the scene from outside (it was originally inside at (0, 0, 6.5)).

## Camera controls (mouse)
- Standard mouse camera controls via Three.js `OrbitControls` (three/addons/controls/OrbitControls.js): left-drag orbits around the sphere center (target 0,0,0), mouse wheel zooms, right-drag pans.
- Damping enabled (dampingFactor 0.08) for smooth motion; distance clamped to 2–8.5 so the camera stays inside the cube sphere (radius 9).
- `controls.update()` runs every frame in the animation loop.
- The key light follows behind the camera every frame (camera position minus 4 units along the camera view direction, lifted 2.5 up), so the "light behind camera" behavior keeps working while orbiting.

## Rotation
- The whole sphere group rotates around all 3 axes (x 0.12, y 0.17, z 0.09 rad/s).
- Each cube rotates around all 3 axes at its own random speed (0.15–1.75 rad/s per axis).

## Materials and lighting
- Cubes: metallic reflective dark red (`MeshStandardMaterial`, color 0x7a0f12, metalness 1.0, roughness 0.28), with a PMREM `RoomEnvironment` map so reflections are real.
- Light source is a point light that sits behind the camera (initial position (0, 2.5, 11), recomputed each frame to follow the camera), so it affects all cubes in the scene; a faint warm ambient fill keeps the far side of the shell visible.

## Scrolling text
- 3D extruded text "Example 1 vibe demo that shows what might be possible using local LLM and limited amount of time fo show usable result." in the Google Font **Orbitron** (geometric sci-fi style; the page also imports Manufacturing Consent + Orbitron CSS, chosen font: Orbitron), rendered at weight **700** via the font's wght variation axis (opentype `variations: { wght: 700 }` option for paths and advance widths). 3D glyphs need outlines, so the Orbitron variable TTF is loaded from the google/fonts GitHub repo (`ofl/orbitron/Orbitron[wght].ttf`, URL-encoded), parsed via `opentype.js` (esm.sh CDN, in the import map); each glyph's outline is converted to THREE Shapes and built with `ExtrudeGeometry` (no helvetiker typeface JSON / TextGeometry anymore).
- Glyphs are big (size 0.5, extrusion depth 0.15) and beveled (bevel thickness 0.02, bevel size 0.01, 2 bevel segments — bevel shrunk so it does not fill glyph counters). Each glyph's front/back cap faces get the same subdivision as the center title: `subdivideCapFaces(geo, 3)` after the 180° X rotation, then `mergeVertices` + `computeVertexNormals` → smooth normals and sweeping reflection gradients across the letter faces.
- Circle lies in the XZ plane (rotation axis Y), radius 4.5, centered at the sphere center, so the text scrolls horizontally in front of the camera, moving right-to-left at the near point (0, 0, 4.5) with forwards reading order (successive characters appear left-to-right on screen).
- Glyph queue: glyphs are laid out by advance width from angle 0 (no invisible lead-space glyphs). Each glyph enters at the far point from the camera (0, 0, -4.5), makes a full circle, then exits at the entry point; glyphs not yet entered and already exited are hidden. Entry is tracked by counting entered letters: a glyph counts as entered once `entryAngle + glyphAngle` passes the entry boundary p = 2π, and because glyph angles ascend with index, entries form a prefix of the queue (reading order). When the LAST letter enters (lettersEntered = 98, the total), the cycle renormalizes to the pure text span (8.4 rad) via a mod wrap, which keeps every on-circle position exactly the same (verified, max diff 8.9e-16 rad), so the last letter stays entering at the far point and the first letter follows right behind. The cycle's head–tail wrap gap is ~0.06 rad, far below the 2π visible window, so from the switch on the circle is continuously populated.
- On every page load/refresh the scroll begins with an EMPTY circle (no lead glyphs): `entryAngle` is initialized to `2π + glyphAngles[0] + charSpacing`, so the first glyph starts just outside the entry boundary and `lettersEntered = 0` — nothing is on the circle at t = 0. Letters enter one by one at the far point in reading order as entryAngle decreases (verified from the first animation frame: 0 visible at t = 0, visible/entered counts growing 2, 5, 8, 11, …). The circle is empty only at the beginning. The switch fires when the LAST letter enters (lettersEntered = 98, at t ≈ 33.6 s), and the stream then repeats from the beginning with the first letter following the last, continuously thereafter (verified: 0 empty windows after the switch, min 71 visible).
- Glyph orientation: no camera-facing billboard. Each glyph's baseline aligns to the circle tangent (pointing along the direction of travel), glyphs stay upright (world +Y up), and the readable face points outward from the circle center. opentype paths are in canvas coordinates (y down), so each glyph geometry is rotated 180° around X — this flips glyphs upright in THREE coords (they were upside-down) and puts the extruded readable face at local +Z. Orientation is built from a basis matrix (travel direction, world up, their cross product).
- Glyph counters (holes in o, e, a, p, d, …): inner contours are detected by containment (smallest enclosing contour, ray-cast test, shoelace areas) and registered as `shape.holes` of their parent contour, so counters are extruded as holes, not filled discs.
- Glyph spacing is proportional to glyph size: each glyph is placed using the font's advance width (`glyph.advanceWidth / font.unitsPerEm` × glyph size, from opentype.js, divided by radius 4.5 to get its angular advance), with a small uniform extra gap of charSpacing 0.01 rad between glyphs (tightened 0.06 → 0.02 → 0.01 rad, which made glyphs look too far apart). Spaces consume the font's space advance × 1.5 (`SPACE_SCALE = 1.5`, no mesh), so word gaps are 1.5x the font space advance. Each glyph's ink is centered within its advance slot (translated by −(min.x + ink-width/2)) so the font's side bearings do not add extra visible gaps.
- Scroll speed 0.25 rad/s (slowed 2x twice, 0.5 → 0.25 → 0.125, fine-tuned to 0.15, then set back to 0.25 by hand); glyph circle position is `p = (entryAngle + glyphAngle) mod totalAngle` with entryAngle decreasing (rotation right-to-left). totalAngle is the text angular span; a glyph is on the circle when `p ∈ [0, 2π]`, entering/exiting at `p = 2π` (the far point).
- Text material is metallic reflective bright blue (color 0x1a4fd6, metalness 1.0, roughness 0.15, slight emissive, env map intensity 2.0). Its `envMap` is the cubemap rendered by a `CubeCamera` placed at the sphere center, so the glyphs reflect the actual rotating cube shell (and the center title), live.

## Center title "Cyberlabs"
- Large 3D extruded text "Cyberlabs" at the scene center, same Orbitron font rendered at the **boldest weight 900** (`centerOpts = { variations: { wght: 900 } }`, the font's wght axis max — thicker, bolder strokes than the scroll glyphs at 700). Built as ONE single mesh: the whole string is laid out by opentype (`font.getPath(centerText, -centerW/2, 0, size, centerOpts)`), so every glyph is placed by advance width and kerning on the shared baseline y = 0, and the entire path (all contours, with counters as holes) is extruded in a single `ExtrudeGeometry` call — not per-glyph meshes.
- Glyph size 1.55 (bigger, bulkier letters), extrusion depth 0.35, beveled (thickness 0.08, size 0.045, 3 segments — the larger bevel expands strokes so letters read thicker and bolder), curveSegments 8. The geometry is rotated 180° around X (canvas y-down → upright); front/back cap faces are then subdivided (triangle mid-point subdivision × 3 → 64× finer cap triangles, via `subdivideCapFaces`), vertices merged and smoothed (`mergeVertices` + `computeVertexNormals`) so reflections sweep as gradients across the letters, and the whole bounding box is centered on the origin, so all glyph baselines stay aligned.
- Material: darker shiny chrome (`MeshStandardMaterial`, color 0xbcc0cb a bit darker, metalness 0.9, roughness 0.05 sharp mirror reflections, env map intensity 3.0, slight emissive 0x101018 × 0.3). Its `envMap` is the cubemap rendered by a second `CubeCamera` (`cubeCamTitle` at the sphere center, 1024 px, mipmapped), captured WITH the scroll glyphs visible and the title hidden, so the chrome letters reflect the rotating cube shell AND the scrolling glyphs live. The scroll text cubemap is also 1024 px (both `WebGLCubeRenderTarget`s raised from 256 px).
- A dedicated white shine point light (`centerShineLight`, intensity 800, distance 25, decay 2) sits in front of the title at (0, 4, 8), giving the chrome letters strong front highlights — the key light behind the camera alone left the letter sides dark.
- Rotates slowly around the Y axis at 0.12 rad/s in the opposite direction of the scroll text (the scroll's effective rotation around Y is negative, so the title uses positive angular velocity).

## Rotating rings around the center title
- Two flat annulus ring bands around the center title, sized so the inner radius is BIGGER than the center title (radii 5.43–5.45 and 6.43–6.45; the center title ink spans x ±4.33, half-width 4.38, so inner radii 5.43 and 6.43 clear it; plates pass outside the scroll circle at radius 4.5 as they rotate). Built with `annulusGeometry(outerR, innerR, depth)` (THREE.Shape circle + circular Path hole → `ExtrudeGeometry`, centered on its own plane, curveSegments 96, no bevel).
- Ring sizes: ring 1 outer 5.45 / inner 5.43, ring 2 outer 6.45 / inner 6.43 — very thin radial bands (band width 0.02) on deep plates (depth 0.56); ring 2 starts tilted (`rotation.set(π/3, 0, 0)`) so the two rings' planes differ.
- Material: dimmer darker glowing, SEMI-TRANSPARENT (opacity 0.8) green, FILLED solid (`MeshStandardMaterial`, color 0x16773a dimmer darker green, emissive 0x118632 dimmer darker glowing green, roughness 0.25, metalness 0.2, `side: DoubleSide`, `transparent: true`, `opacity: 0.8`, `wireframe: false` — solid band plates, wireframe removed per Change 30). ONE shared material instance for both rings so the flicker is in sync.
- Glow flicker: every frame the shared material's `emissiveIntensity` is recomputed as `0.35 + 0.25·sin(141.0·t) + 0.18·sin(237.0·t + 1.7) + 0.16·random` (floored at 0.04), where t is accumulated time — two incommensurate sine frequencies (~22.4 Hz and ~37.7 Hz, 3x the previous 47.0/79.0) plus per-frame random jitter give a very rapid, uneven flicker: the band glow pulses bright green, drops toward dark green, irregularly (at 120 fps the 37.7 Hz component aliases into visible fast beats, so the flicker reads as rapid shimmer).
- Each ring is in its own group (`ringGroup1`, `ringGroup2`) and rotates at its own speed (set by hand: ring 1 x 0.70, y 1.30 rad/s, z axis commented out; ring 2 x 0.50, y 0.60, z 0.20 rad/s — all three axes active).
- Ring glow via selective bloom post-processing: `UnrealBloomPass` (strength 0.2, radius 0.3, threshold 0.85 — tightened from 1.2/0.6/0.2 → 0.45/0.4/0.65 → 0.25/0.3/0.8 to reduce the glow halo) on a `bloomComposer` (`EffectComposer`, renderToScreen false); ring meshes are tagged `userData.bloom = true`, and every frame all non-bloom meshes are temporarily swapped to a black material for the bloom render, materials restored, then a `finalComposer` renders the scene and composites the bloom texture additively via a `ShaderPass` (baseTexture + bloomTexture), with `OutputPass` applying tone mapping/sRGB. `composer.setSize` wired into the resize handler.
